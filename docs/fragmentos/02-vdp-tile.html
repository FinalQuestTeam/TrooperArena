vdp_tile.h Operações gerais de tile e tilemap no VDP

Este módulo fornece as rotinas de baixo nível para manipular tiles e tilemaps no VDP (Video Display Processor) do Mega Drive: envio de dados de tile (patterns de 8x8 pixels, 4bpp) para a VRAM, conversão "on the fly" de bitmaps 4bpp em tiles, e limpeza/preenchimento/escrita de dados de tilemap nos planes de fundo (BG_A, BG_B e WINDOW). No hardware, cada entrada de tilemap é uma word de 16 bits que combina o índice do tile (11 bits) com atributos de prioridade, paleta e flip horizontal/vertical — as macros TILE_ATTR() e TILE_ATTR_FULL() codificam esse formato. Use este módulo sempre que precisar carregar gráficos de fundo, montar telas estáticas, atualizar linhas/colunas de tilemap para scrolling contínuo ou simular um frame buffer. A maioria das funções aceita um parâmetro TransferMethod (CPU, DMA, DMA_QUEUE ou DMA_QUEUE_COPY) que define como os dados chegam à VRAM.

Tipos

TileSet

Estrutura que contém a definição de um conjunto de tiles (patterns). Se o campo de compressão indicar dados comprimidos, use unpackTileSet() para descomprimir, ou deixe que as funções de carga descompactem "on the fly".

typedef struct
{
    u16 compression;  // tipo de compressão: COMPRESSION_NONE, COMPRESSION_APLIB ou COMPRESSION_LZ4W
    u16 numTile;      // número de tiles no buffer 'tiles'
    u32 *tiles;       // dados dos tiles (comprimidos ou não, conforme 'compression')
} TileSet;

TileMap

Estrutura que contém a definição de um tilemap de fundo (matriz de entradas de 16 bits com índice + atributos de tile). Se comprimido, use unpackTileMap() ou deixe as funções de carga descompactarem quando necessário.

typedef struct
{
    u16 compression;  // tipo de compressão: COMPRESSION_NONE, COMPRESSION_APLIB ou COMPRESSION_LZ4W
    u16 w;            // largura do tilemap (em tiles)
    u16 h;            // altura do tilemap (em tiles)
    u16 *tilemap;     // dados do tilemap
} TileMap;

Funções

TILE_ATTR(pal, prio, flipV, flipH)

Macro com comportamento de função que codifica os atributos de tile (sem o índice) para dados de tilemap, no formato de 16 bits usado pelo hardware do VDP.

ParâmetroDescrição
palÍndice da paleta (0 a 3 — PAL0..PAL3).
prioPrioridade do tile (0 = baixa, 1 = alta; tiles de alta prioridade são desenhados sobre sprites de baixa prioridade).
flipVFlip vertical (0 ou 1).
flipHFlip horizontal (0 ou 1).

Retorna: valor de 16 bits com os atributos combinados, pronto para ser somado a um índice de tile.

TILE_ATTR_FULL(pal, prio, flipV, flipH, index)

Macro com comportamento de função que codifica os atributos de tile e o índice do tile em uma única word de tilemap.

ParâmetroDescrição
palÍndice da paleta (0 a 3).
prioPrioridade do tile (0 ou 1).
flipVFlip vertical (0 ou 1).
flipHFlip horizontal (0 ou 1).
indexÍndice do tile na VRAM (0 a 2047).

Retorna: entrada de tilemap completa (16 bits) pronta para escrita no plane.

void VDP_loadTileData(const u32 *data, u16 index, u16 num, TransferMethod tm)

Carrega dados de tile (patterns de 8x8 pixels, 32 bytes por tile) na VRAM a partir do índice indicado.

ParâmetroDescrição
dataPonteiro para os dados de tile (já no formato nativo do VDP).
indexÍndice de tile onde iniciar a carga (use TILE_USER_INDEX como base para tiles do usuário).
numNúmero de tiles a carregar.
tmMétodo de transferência: CPU, DMA, DMA_QUEUE ou DMA_QUEUE_COPY.

Taxa de transferência aproximada: ~90 bytes por scanline via software e ~190 bytes por scanline via DMA (durante o blanking).

bool VDP_loadTileSet(const TileSet *tileset, u16 index, TransferMethod tm)

Carrega um TileSet completo na VRAM. Se o TileSet estiver comprimido, é descompactado "on the fly" (requer memória temporária).

ParâmetroDescrição
tilesetPonteiro para a estrutura TileSet.
indexÍndice de tile onde iniciar a carga (base: TILE_USER_INDEX).
tmMétodo de transferência: CPU, DMA, DMA_QUEUE ou DMA_QUEUE_COPY.

Retorna: FALSE se não houver memória suficiente para descompactar o TileSet (apenas quando há compressão).

Usar DMA_QUEUE com recurso comprimido é inseguro: o buffer descompactado é liberado e pode ser sobrescrito antes de o DMA executar. Nesse caso use DMA_QUEUE_COPY ou descompacte o recurso antes.

bool VDP_loadTileSetEx(const TileSet *tileset, u16 index, u16 fromTile, u16 count, TransferMethod tm)

Carrega apenas um subconjunto de tiles de um TileSet na VRAM. Útil para recarregar parte de um tileset sobrescrito ou, em mapas com streaming, para extrair somente os tiles necessários de um atlas completo.

ParâmetroDescrição
tilesetPonteiro para a estrutura TileSet (descompactada "on the fly" se necessário).
indexÍndice de tile em VRAM onde iniciar a carga.
fromTileÍndice do primeiro tile do conjunto a ser carregado.
countNúmero de tiles a carregar.
tmMétodo de transferência: CPU, DMA, DMA_QUEUE ou DMA_QUEUE_COPY.

Retorna: FALSE se não houver memória para descompactar o TileSet (apenas com compressão).

Mesma ressalva de VDP_loadTileSet() quanto a DMA_QUEUE com recursos comprimidos.

void VDP_loadFontData(const u32 *font, u16 length, TransferMethod tm)

Carrega dados de tile de uma fonte na VRAM, substituindo a fonte do sistema. Os dados são gravados a partir de TILE_FONT_INDEX; cada caractere ocupa um tile de 8x8 pixels.

ParâmetroDescrição
fontPonteiro para os dados de tile da fonte.
lengthNúmero de caracteres da fonte (máximo FONT_LENGTH).
tmMétodo de transferência: CPU, DMA, DMA_QUEUE ou DMA_QUEUE_COPY.

Prefira VDP_loadFont(), mais simples de usar. Veja também VDP_loadTileData().

bool VDP_loadFont(const TileSet *font, TransferMethod tm)

Carrega uma fonte a partir de um TileSet na VRAM, substituindo a fonte do sistema. O TileSet deve conter uma fonte de 16x6 caracteres (veja a fonte padrão do SGDK em res\image\font_default.png).

ParâmetroDescrição
fontTileSet contendo a fonte (descompactado "on the fly" se necessário).
tmMétodo de transferência: CPU, DMA, DMA_QUEUE ou DMA_QUEUE_COPY.

Retorna: FALSE se não houver memória para descompactar a fonte (apenas com compressão).

Com recurso comprimido evite DMA_QUEUE; use DMA_QUEUE_COPY ou descompacte antes. Os dados vão para TILE_FONT_INDEX, com no máximo FONT_LENGTH caracteres.

void VDP_loadBMPTileData(const u32 *data, u16 index, u16 w, u16 h, u16 bmp_w)

Carrega dados de bitmap 4bpp na VRAM convertendo-os "on the fly" para o formato de tile do VDP. Muito útil ao trabalhar com imagens bitmap, mas a conversão consome tempo: use apenas em telas estáticas. Em situação de jogo, prefira VDP_loadTileData() com dados já convertidos.

ParâmetroDescrição
dataPonteiro para os dados de bitmap 4bpp.
indexÍndice de tile onde iniciar a carga (base: TILE_USER_INDEX).
wLargura da região do bitmap a carregar (em tiles).
hAltura da região do bitmap a carregar (em tiles).
bmp_wLargura total do bitmap (em tiles); pode diferir de w.

Veja também VDP_loadBMPTileDataEx().

void VDP_fillTileData(u8 value, u16 index, u16 num, bool wait)

Preenche dados de tile na VRAM com um valor de byte. Geralmente usada para limpar (zerar) tiles na VRAM. Internamente utiliza a operação de VRAM Fill do VDP.

ParâmetroDescrição
valueValor (byte) usado no preenchimento.
indexÍndice de tile onde iniciar o preenchimento (base: TILE_USER_INDEX).
numNúmero de tiles a preencher.
waitSe TRUE, aguarda a conclusão da operação; se FALSE, retorna imediatamente — nesse caso é preciso esperar o fim do DMA (DMA_waitCompletion()) antes de acessar o VDP.

vdp_spr.h Suporte de baixo nível a sprites do VDP

Este módulo fornece métodos para alocar e manipular sprites de hardware do VDP em baixo nível. O VDP do Mega Drive/Genesis gerencia até 80 sprites simultâneos (em modo H40; 64 em H32), cada um com até 4x4 tiles (32x32 pixels). Os sprites são descritos na SAT (Sprite Attribute Table) em VRAM e encadeados pelo campo link, que define a ordem de avaliação/desenho. O SGDK mantém um cache da SAT em RAM (vdpSpriteCache): as funções VDP_setSprite* alteram o cache, e VDP_updateSprites() envia o cache ao VDP (idealmente via DMA no VBlank). Para uso de alto nível, prefira a engine de sprites (sprite_eng.h); use este módulo quando quiser controle manual e mínimo overhead.

Constantes, macros e variáveis globais

NomeValorDescrição
SAT_MAX_SIZE80Tamanho máximo da Sprite Attribute Table usada pelo SGDK (a SAT comporta 128 entradas em VRAM, mas o VDP limita a exibição a 80 sprites).
vdpSpriteCacheVDPSprite[SAT_MAX_SIZE + 16]Variável global: cache em RAM da lista de sprites do VDP.
lastAllocatedVDPSpriteVDPSprite*Variável global: ponteiro para o último sprite alocado por VDP_allocateSprites(); útil para encadear (link) a partir do fim da lista alocada.
highestVDPSpriteIndexs16Variável global: maior índice de sprite alocado desde o último VDP_resetSprites() / VDP_releaseAllSprites() (-1 = nenhum). Atenção: não é atualizada corretamente em liberações; use VDP_refreshHighestAllocatedSpriteIndex() para recalcular.

Tipos

VDPSprite

Estrutura que replica o formato de um sprite de hardware do VDP (entrada de 8 bytes da SAT). As posições X e Y são deslocadas de 0x80 (0x80 corresponde à posição 0 na tela), o que permite esconder sprites fora da área visível.

typedef struct
{
    s16 y;                       // posição Y - 0x80 (0x80 = 0 na tela), 10 bits [0-1023]
    union
    {
        struct
        {
            u16 unused1  : 4;
            u16 sizeH    : 2;    // largura: 0=8, 1=16, 2=24, 3=32 pixels
            u16 sizeV    : 2;    // altura:  0=8, 1=16, 2=24, 3=32 pixels
            u16 unused2  : 1;
            u16 linkData : 7;    // link para o próximo sprite (0 = fim da lista)
        };
        struct
        {
            u8 size;             // tamanho combinado (veja SPRITE_SIZE)
            u8 link;             // link (ordem de desenho)
        };
        u16 size_link;
    };
    union
    {
        u16 attribut;            // índice do tile + atributos (veja TILE_ATTR_FULL)
        struct
        {
            u16 priority : 1;    // prioridade: 0=baixa, 1=alta
            u16 palette  : 2;    // índice da paleta [0-3]
            u16 flipV    : 1;    // flip vertical
            u16 flipH    : 1;    // flip horizontal
            u16 tile     : 11;   // índice do tile [0-2047]
        };
    };
    s16 x;                       // posição X - 0x80 (0x80 = 0 na tela), 10 bits [0-1023]
} VDPSprite;

vram.h Alocação dinâmica de VRAM para tiles

Unidade de gerenciamento de VRAM (memória de vídeo) do SGDK. Oferece alocação dinâmica de blocos de tiles dentro de uma região de VRAM, no estilo de um alocador de heap: você cria uma VRAMRegion cobrindo uma faixa de índices de tile, e então aloca (VRAM_alloc) e libera (VRAM_free) blocos conforme a necessidade — é o mecanismo usado, por exemplo, pela engine de sprites para carregar tiles sob demanda. Por convenção, os dados de tile devem ficar antes dos tilemaps na VRAM (0000-XXXX = tile data, XXXX-FFFF = tilemaps). Internamente, o campo vram da região é um buffer de contabilidade em que cada entrada guarda o tamanho do bloco em tiles (bits b14-b0) e um bit de estado (b15 = 1 usado, 0 livre); blocos livres adjacentes são reaproveitados nas próximas alocações.

Tipos

VRAMRegion

Estrutura que define uma região de VRAM dedicada ao armazenamento dinâmico de tiles, com as informações de cache/contabilidade da alocação.

{
    u16 startIndex;  // posição inicial da região (em tiles)
    u16 endIndex;    // posição final da região (em tiles)
    u16 *free;       // posição da próxima área livre
    u16 *vram;       // buffer de contabilidade da alocação
                     //   b14-b0 = tamanho do bloco (em tiles)
                     //   b15    = 1: usado, 0: livre
} VRAMRegion;

pal.h Paletas de cor do VDP (CRAM) e efeitos de fade

Unidade de suporte a paletas (herdeira da antiga vdp_pal.h). O VDP do Mega Drive possui 4 paletas de 16 cores (64 entradas no total) armazenadas na CRAM (Color RAM). Cada cor usa 3 bits por componente no formato de 16 bits xxxxBBBxGGGxRRRx (RGB333). Este módulo oferece leitura e escrita de cores/paletas na CRAM (com métodos de transferência CPU/DMA), macros de conversão de RGB de 24 bits para o formato do VDP e um conjunto completo de efeitos de fade: assíncronos (processados a cada frame pelo sistema), síncronos (bloqueantes) e manuais (controlados passo a passo pela aplicação com PAL_initFade() / PAL_doFadeStep()).
