sys.h Ponto de entrada, interrupções e sistema

Unidade central do SGDK: contém os métodos de inicialização e reset, o processamento de VBlank e o gerenciamento de interrupções e callbacks. O Mega Drive possui três interrupções principais no 68000: a V-Int (interrupção vertical, nível 6), disparada ao final do período de exibição, no início do vertical blank — é o "coração" do jogo, usada para sincronizar a lógica com a taxa de quadros; a H-Int (interrupção horizontal, nível 4), disparada ao final de cada scanline (ou a cada N scanlines, conforme configurado no VDP) — usada para efeitos de raster no meio do quadro (troca de paleta, scroll por linha etc.); e a Ext-Int (interrupção externa, nível 2), disparada pelo gatilho de Light Gun. Para cada uma delas você pode registrar um callback próprio (SYS_setVIntCallback, SYS_setHIntCallback, SYS_setExtIntCallback), além do callback de VBlank (SYS_setVBlankCallback), chamado pelo SGDK dentro de SYS_doVBlankProcess() após as tarefas principais — é o local recomendado para acessos ao VDP. Use este módulo em todo projeto: o laço principal típico termina cada quadro com SYS_doVBlankProcess(), que descarrega a fila de DMA, processa fades de paleta assíncronos e faz o polling dos joypads. O módulo também oferece controle da máscara de interrupções (SYS_disableInts/SYS_enableInts), detecção NTSC/PAL, medição de FPS/carga de CPU, checksum da ROM e término com mensagem de erro (SYS_die).

bool SYS_doVBlankProcess(void)

Espera o início do VBlank e executa todo o processamento de VBlank do SGDK: descarrega a fila de DMA, processa a operação assíncrona de fade de paleta e faz o polling dos joypads. As transferências de dados para o VDP devem ocorrer nesse período, pois o VDP está ocioso. Equivale a SYS_doVBlankProcessEx(ON_VBLANK_START).

Retorna: FALSE se o processo foi cancelado por ter sido chamado de dentro do callback de V-Int (a função sai pois a V-Int será disparada imediatamente).

Se o início do VBlank for perdido, o processamento é adiado para o próximo VBlank, causando a perda de um quadro.

bool SYS_doVBlankProcessEx(VBlankProcessTime processTime)

Versão estendida de SYS_doVBlankProcess() que permite escolher em que momento o processamento de VBlank começa (fila de DMA, fade de paleta, polling de joypad...).

ParâmetroDescrição
processTimeIMMEDIATELY = inicia imediatamente, esteja ou não em blanking (fortemente desaconselhado); ON_VBLANK = inicia no período de VBlank, imediatamente se já estivermos nele (desaconselhado, o VBlank pode ficar curto demais); ON_VBLANK_START = espera o próximo início de VBlank (valor recomendado, garante DMA rápido e evita glitches gráficos por atualização de VRAM durante o display ativo).

Retorna: FALSE se o processo foi cancelado (com ON_VBLANK_START) por ter sido chamado do callback de V-Int.

void SYS_disableInts(void)

Desabilita as interrupções (vertical, horizontal e externa). Use para proteger trechos de código sensíveis (em geral acessos a portas de I/O ou ao VDP quando seus callbacks de interrupção também mexem no VDP). Deve sempre ser seguida por SYS_enableInts().

As chamadas SYS_disableInts() / SYS_enableInts() podem ser aninhadas. Por padrão o SGDK não faz nada "perigoso" nos seus handlers de interrupção (exceto na engine Bitmap), então a proteção só é necessária se o seu callback de interrupção manipular o VDP.

void SYS_enableInts(void)

Reabilita as interrupções após uma chamada a SYS_disableInts(). Suporta aninhamento.

void SYS_setVBlankCallback(VoidCallback *CB)

Define o callback de usuário do período de VBlank. O SGDK o chama de dentro de SYS_doVBlankProcess(), após as tarefas principais. É o callback recomendado (em vez do de V-Int) quando você precisa fazer acessos ao VDP, pois roda em contexto normal, fora da interrupção.

ParâmetroDescrição
CBPonteiro para o método a chamar no VBlank; passe NULL para remover o callback atual.

void SYS_setVIntCallback(VoidCallback *CB)

Define o callback de interrupção vertical (V-Int), que ocorre no fim do período de exibição, no início do VBlank. Prefira SYS_setVBlankCallback() quando possível. O SGDK só processa obrigatoriamente na V-Int o tempo da música do driver XGM e o reset de fase da engine Bitmap.

ParâmetroDescrição
CBPonteiro para o método a chamar na V-Int; NULL remove o callback.

Mantenha o código do callback o mais rápido possível (ele consome tempo precioso de VBlank) e evite tocar no VDP a partir dele — caso contrário será preciso proteger todos os acessos ao VDP do laço principal.

Define o callback de interrupção horizontal (H-Int), disparada ao final da exibição de cada scanline, logo antes do horizontal blank. Usada para efeitos de raster no meio do quadro (troca de paleta, scroll, etc.). A função de callback precisa ser declarada com o prefixo HINTERRUPT_CALLBACK:

memory.h Alocação dinâmica e operações de memória

Fornece operações de cópia/preenchimento de memória e alocação dinâmica de memória na RAM do Mega Drive. A memória gerenciada é organizada em blocos: os 2 primeiros bytes de cada bloco definem seu tamanho e estado — bits 15-1 = tamanho em número de words (2 bytes), bit 0 = estado de uso (1 = usado, 0 = livre). Para alcançar o bloco seguinte basta fazer next_bloc_address = bloc_address + bloc_size; o fim da memória é marcado por um bloco de tamanho 0. Use este módulo sempre que precisar de malloc/free (com ENABLE_NEWLIB == 0, malloc e free são mapeados para MEM_alloc/MEM_free), de memset/memcpy otimizados, ou de diagnóstico do heap (fragmentação, integridade, dump).

dma.h Transferências DMA e fila de DMA

Fornece os métodos para usar as capacidades de DMA do hardware — a forma mais rápida de transferir dados da ROM/RAM do 68000 para as memórias do VDP (VRAM, CRAM e VSRAM). O conceito central é a fila de DMA (DMA queue): em vez de executar cada transferência na hora, você a enfileira durante o quadro (DMA_queueDma, DMA_copyAndQueueDma, DMA_allocateAndQueueDma ou DMA_transfer com DMA_QUEUE) e todas as operações pendentes são disparadas em rajada por DMA_flushQueue() — chamada automaticamente no VBlank por SYS_doVBlankProcess() quando o auto-flush está ativo. Transferir durante o VBlank é essencial por dois motivos: o VDP está ocioso (a banda de DMA disponível é muito maior — cerca de 7,2 KB por VBlank em NTSC e até 15 KB em PAL), e escrever na VRAM durante o display ativo pode causar glitches visuais além de ser bem mais lento. O módulo também oferece transferências imediatas (DMA_doDma), cópia por CPU para testes (DMA_doCPUCopy), operações de fill/copy internas da VRAM, um buffer temporário associado à fila e controles de capacidade máxima por quadro (para limitar o custo do flush e evitar slowdowns).

task.h Tarefa de usuário (multitarefa cooperativa)

Permite registrar uma função que executa como tarefa de usuário (user task), num esquema de multitarefa cooperativa com a tarefa supervisora (o seu laço principal). O tempo de CPU é cedido à tarefa de usuário de duas formas: quando a tarefa supervisora chama TSK_userYield(), a tarefa de usuário executa imediatamente até a próxima interrupção de VBlank, quando a supervisora é retomada; ou quando a supervisora chama TSK_superPend(), a tarefa de usuário executa até que (a) ela própria chame TSK_superPost() ou (b) o timeout especificado expire. Útil para aproveitar o tempo ocioso do quadro com trabalho em segundo plano (descompressão, IA, streaming...). Para o escalonador funcionar, as interrupções de VBlank precisam estar habilitadas. As funções são implementadas em task.s (assembly).

Inicializa o subsistema de tarefas (reseta as variáveis internas).

Configura a função de callback da tarefa de usuário. Deve ser definida com um callback não nulo antes de chamar qualquer outra função TSK_xxx.

ParâmetroDescrição

Para a tarefa de usuário. Tem o mesmo efeito que TSK_userSet(NULL).

Cede o controle da tarefa supervisora para a tarefa de usuário. A tarefa de usuário será retomada e usará todo o tempo de CPU disponível até a próxima interrupção de VBlank, que retoma a tarefa supervisora.

Bloqueia a tarefa supervisora e retoma a tarefa de usuário. A supervisora só retoma a execução quando TSK_superPost() for chamada pela tarefa de usuário ou quando o timeout expirar.

ParâmetroDescrição

pool.h Pool de objetos (alocação a partir de conjunto fixo)

Unidade de gerenciamento de alocação dinâmica de objetos a partir de um conjunto fixo, pré-alocado — o Pool. Ideal para entidades de jogo com quantidade máxima conhecida (balas, inimigos, partículas): a alocação e a liberação são muito rápidas (pilha de alocação), sem fragmentar o heap. Exemplo: Pool* bulletPool = POOL_create(20, sizeof(Bullet)); e depois Bullet* bullet = POOL_allocate(bulletPool); (verificando NULL) e POOL_release(bulletPool, bullet, ...) ao terminar. O Pool também é muito útil para iterar rapidamente sobre os objetos alocados, combinando POOL_getFirst() com POOL_getNumAllocated():

Bullet** bullets = POOL_getFirst(bulletPool);
u16 num = POOL_getNumAllocated(bulletPool);
while(num--)
{
    Bullet* bullet = *bullets++;
    /* faça o que precisar com o bullet */
}

config.h Flags de compilação da biblioteca

Arquivo de configuração básica da biblioteca SGDK: define as opções específicas de compilação. Cada flag é um #define avaliado em tempo de compilação — alterar qualquer uma exige recompilar a biblioteca. Elas controlam desde comportamento de hardware (parar o Z80 durante DMA ou acesso a I/O, para contornar bugs de alguns modelos de Mega Drive), passando por escolhas de engine (sprite engine legada ou nova, error handler legado ou o do MD Debugger, posição da fonte na VRAM), até a habilitação de módulos opcionais (EverDrive, FAT16, Serial, MegaWiFi, Flash Save, console TTY, Link Cable) e recursos como bank switching automático para ROMs > 4 MB, uso da newlib e o logo de introdução do kit. O arquivo também contém verificações de dependência entre módulos (por exemplo, FAT16 exige EverDrive; a implementação "cross" do MegaWiFi exige o módulo Serial) que geram #error em combinações inválidas. Não declara funções.

HALT_Z80_ON_DMA1Força a parada (halt) do Z80 durante operações de DMA (padrão). Alguns modelos de Mega Drive precisam disso para evitar corrupção da transferência DMA, ou até leitura inválida da memória do 68000/Z80 em casos muito raros (quando o Z80 acessa o barramento principal exatamente no disparo do DMA). Só desabilite se tiver 100% de certeza de que evita esse caso (por sua conta e risco).
HALT_Z80_ON_IO1Força a parada do Z80 durante acessos às portas de I/O (controles). Alguns modelos (como certos MD2) precisam disso para evitar raros bugs de corrupção do Z80.
DMA_DISABLED0Com 1, desabilita completamente as transferências DMA (para testes), substituindo-as por cópia (mais lenta) via CPU.
LEGACY_SPRITE_ENGINE0Com 1, usa a sprite engine antiga em vez da nova. A antiga permite acessar/alterar os índices internos de sprite do VDP (útil para multiplexação de sprites); a nova usa melhor os sprites do VDP, permitindo exibir um pouco mais de sprites na prática.
LEGACY_ERROR_HANDLER0Com 1, usa a tela de erro e os vetores originais do SGDK. Com 0, usa o error handler do projeto MD Debugger, que suporta símbolos do código-fonte (perfil "debug") e backtrace — mas toma conta dos vetores de exceção e não permite registrar callbacks próprios de erro (ex.: addressErrorCB). Se você depende desses callbacks, use o sistema legado.
LEGACY_FONT_LOCATION1Com 1, mantém o tileset da fonte na posição original da VRAM (fim do espaço de tiles). Com 0, move a fonte para o início da VRAM, liberando o espaço completo de tiles para os assets do jogo e evitando problemas de fragmentação de VRAM (ver TILE_FONT_INDEX).
ENABLE_BANK_SWITCH0Com 1, habilita a troca automática de banco usando o mapper oficial da SEGA para ROMs > 4 MB. Os dados BIN internos declarados na seção .far_rodata passam a ser acessados via BANK_getFarData(..) (mapper.c), o que pode impactar bastante a performance — por isso vem desabilitado por padrão.
ENABLE_NEWLIB0Com 1, usa a newlib com o SGDK: desabilita os métodos padrão do SGDK (memset/memcpy/malloc...) substituindo-os pelas implementações da newlib.
ENABLE_LOGO0Com 1, exibe o logo de introdução do kit na inicialização.
ZOOMING_LOGO0Com 1 (e ENABLE_LOGO ativo), usa efeito de zoom no logo de introdução em vez do fade clássico.
MODULE_EVERDRIVE0Com 1, habilita os métodos de programação EVERDRIVE (escritos por Krikzz).
MODULE_FAT160Com 1, habilita os métodos FAT16 para cartucho Everdrive (escritos por Krikzz). Custa um pouco mais de 1 KB de RAM. Exige MODULE_EVERDRIVE (senão gera #error).
MODULE_SERIAL0Com 1, habilita o uso de PORT_2 ou PORT_EXT como porta serial COMM.
MODULE_MEGAWIFI0Com 1, habilita as funções e o código de suporte MegaWiFi (escritos por Jesus Alonso — doragasu).
MEGAWIFI_IMPLEMENTATION_CROSS / _MW_CART / _ED0x01 / 0x02 / 0x04Implementações MegaWiFi disponíveis: Cross (Serial), cartucho MegaWiFi e EverDrive (para testes). MEGAWIFI_IMPLEMENTATION define a combinação usada (padrão: CROSS | ED). Cuidado: habilitar MW_CART e EverDrive juntos pode causar problemas, pois ambos usam a mesma estrutura de vtable COMM. A implementação Cross exige MODULE_SERIAL e a ED exige ENABLE_BANK_SWITCH (senão geram #error).
MODULE_FLASHSAVE1Com 1, habilita as funções de Flash Save (escritas por Jesus Alonso — doragasu). Não há razão para desabilitar, pois não consome memória extra.
MODULE_CONSOLE1Com 1, habilita o módulo de console de texto TTY (escrito por Andreas Dietrich). Consome cerca de 28 bytes de memória quando habilitado.
MODULE_LINK_CABLE0Com 1, habilita as funções do protocolo Link Cable (escritas por BlodTor).
