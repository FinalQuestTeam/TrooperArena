megawifi.h API principal do MegaWiFi

API principal do cartucho MegaWiFi, um cartucho para Mega Drive equipado com um módulo ESP8266 que fornece WiFi e uma pilha TCP/IP completa ao console. Por meio desta API o jogo pode detectar o módulo, configurar redes (SSID, senha, IPv4, SNTP), associar-se a um Access Point, abrir sockets TCP/UDP, realizar requisições HTTP/HTTPS, acessar a flash do módulo, obter data/hora, números aleatórios de hardware, gamertags e ainda usar a Game API (por exemplo, GameJolt). A maioria das chamadas é autoexplicativa; a única particularidade é o modo reuse de UDP: ao passar dst_addr e/ou dst_port como NULL em mw_udp_set(), os dados recebidos passam a vir prefixados com IP e porta do peer (estrutura mw_reuse_payload), e os dados a enviar também exigem esse prefixo. Requer MODULE_MEGAWIFI = 1 em config.h (com reconstrução da biblioteca). Autores: Jesus Alonso (doragasu) e Juan Antonio (PaCHoN).

enum mw_err

Códigos de erro retornados pelas funções da API MegaWiFi.

enum mw_err {
    MW_ERR_NONE = 0,         // Sem erro (sucesso)
    MW_ERR,                  // Erro genérico

    MW_ERR_RECV              // Erro ao receber dados

struct mw_ap_data {

jsmn.h Parser JSON minimalista (jsmn)

O jsmn, de Serge Zaitsev (licença MIT), é um parser de JSON minimalista, sem alocação dinâmica: ele apenas tokeniza a string JSON em um vetor de tokens (jsmntok_t) fornecido pelo chamador, cada token descrevendo um objeto, array, string ou primitivo com suas posições de início e fim. É a base do módulo json.h do SGDK, usado para interpretar respostas JSON recebidas via MegaWiFi. Este header é do tipo header-only: além da API pública (jsmn_init/jsmn_parse), contém a implementação com funções estáticas internas. Comportamentos opcionais são controlados por JSMN_STATIC (API estática), JSMN_HEADER (somente declarações), JSMN_PARENT_LINKS (campo parent nos tokens) e JSMN_STRICT (análise estrita).

lsd.h Protocolo de enlace LSD (Local Symmetric Data-link)

Local Symmetric Data-link: protocolo extremamente simples para ligar dois dispositivos full-duplex, multiplexando o enlace de dados em até LSD_MAX_CH canais simultâneos sobre o link serial — é a camada de enlace usada entre o Mega Drive e o módulo WiFi do MegaWiFi. O módulo tem funções síncronas para enviar/receber (fáceis de usar, mas que fazem polling e travam o console até o fim da transferência) e as equivalentes assíncronas, que retornam imediatamente mas exigem chamadas frequentes a lsd_process(); ao concluírem, executam o callback informado. O formato de frame é STX : CH-LENH : LENL : DATA : ETX (STX/ETX delimitam o frame; CH-LENH traz o canal nos 4 bits altos e os 4 bits altos do comprimento; LENL traz os 8 bits baixos do comprimento). Como o Mega Drive não tem pino de interrupção nem de DMA no slot de cartucho, polling é o único caminho. Aviso: a API síncrona é bem menos confiável — lsd_recv_sync() pode congelar a máquina se nenhum frame for recebido. Autores: Jesus Alonso (doragasu) e Juan Antonio (PaCHoN), 2019~2025.
