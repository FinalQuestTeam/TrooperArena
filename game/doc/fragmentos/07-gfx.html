bmp.h Motor de bitmap por software

Este módulo simula um modo bitmap no Mega Drive/Genesis — hardware que, nativamente, só trabalha com tiles e sprites. O motor emula uma tela bitmap de 256×160 pixels (4bpp, 16 cores) desenhada em RAM e transferida para a VRAM durante os períodos de blank. Ele usa duplo buffer em memória principal: você desenha no buffer de escrita enquanto o buffer de leitura é enviado ao vídeo. Para acelerar a transferência, a área ativa da tela é reduzida (scanlines 32–191 ativas, o resto vira blank estendido), permitindo cerca de 20 atualizações por segundo em NTSC e 25 em PAL.

Custo: o motor aloca dinamicamente cerca de 41 KB de RAM em BMP_init() (liberados em BMP_end()) e consome praticamente toda a VRAM de tiles quando o duplo buffer de VRAM é ativado. Todo o desenho é feito pela CPU (pixel a pixel), portanto é lento comparado ao modo tile normal. Use-o apenas quando realmente precisar de gráficos por pixel: renderização 3D em wireframe/polígonos, efeitos procedurais, plotagem de gráficos etc. Para jogos 2D convencionais, prefira os sistemas de tiles/sprites (vdp_tile.h, sprite_eng.h, map.h).

Tipos

Bitmap

Estrutura de bitmap 4bpp do Genesis, normalmente gerada pelo rescomp a partir de arquivos .bmp/.png. Se houver compressão, use unpackBitmap() para descompactar (ou deixe as funções BMP_drawBitmap* fazerem isso automaticamente).

typedef struct
{
    u16 compression;        // tipo de compressão dos dados de imagem:
                            // COMPRESSION_NONE, COMPRESSION_APLIB ou COMPRESSION_LZ4W

    u16 h;                  // altura em pixels
    const Palette *palette; // dados da paleta (16 cores)
    const u8 *image;        // dados da imagem, tamanho = (w * h / 2);

} Bitmap;

void BMP_setBufferCopy(u16 value)

Ativa/desativa a preservação do conteúdo entre buffers. Como o motor sempre usa duplo buffer em RAM, o conteúdo desenhado não é preservado de um frame para o outro (são dois buffers distintos). u16 BMP_flip(u16 async)

Envia (blit) o back buffer atual para a tela e troca os buffers (o back buffer vira front buffer e vice-versa). No modo assíncrono, a transferência para a VRAM acontece durante o período de blank e a função retorna imediatamente. Se já houver um flip em andamento, a nova solicitação fica pendente e será processada quando o flip atual terminar; se já houver uma solicitação pendente, a função espera até que não haja mais pendências.

ParâmetroDescrição
asyncFlag de operação assíncrona.

Retorna: significativo apenas no modo assíncrono — 0 se a solicitação ficou pendente (outro flip em andamento), 1 se o flip foi iniciado.

Use BMP_waitWhileFlipRequestPending() para garantir que não haja flips pendentes antes de escrever no buffer do bitmap.

map.h Mapas grandes com scrolling e streaming de tiles

Este módulo gerencia mapas de fundo grandes (níveis maiores que a tela) com um motor de scrolling que faz o streaming de tiles sob demanda: ao chamar MAP_scrollTo(..), apenas as novas linhas/colunas de tilemap que entram na área visível são preparadas e enviadas à VRAM pela fila de DMA, e o registro de scroll do VDP é ajustado automaticamente no VBlank (dentro de SYS_doVBlankProcess()). Assim é possível percorrer fundos enormes gastando pouca VRAM e pouca banda de transferência por frame.

O recurso MAP (gerado pelo rescomp) codifica a imagem grande como uma estrutura MapDefinition altamente compactada: o mapa é uma grade de blocos de 128×128 pixels (blocos duplicados guardam só uma referência); cada bloco é uma grade 8×8 de metatiles; cada metatile é um bloco de 16×16 pixels (2×2 tiles), com deduplicação de metatiles repetidos ou espelhados. Ao desenhar o fundo do seu nível, procure maximizar a repetição de blocos 128×128 para reduzir o tamanho do recurso. Além do scrolling, o módulo oferece funções de consulta (MAP_getTile, MAP_getMetaTile, ...) úteis para colisão e lógica de jogo, e um callback de patch para modificar o tilemap antes do envio à VRAM (blocos destrutíveis, por exemplo).

Tipos

MapUpdateType

Tipo de atualização dos dados do mapa, informado ao callback de patch.

typedef enum
{
    ROW_UPDATE,    // atualização de linha do tilemap
    COLUMN_UPDATE  // atualização de coluna do tilemap
} MapUpdateType;

MapDataPatchCallback

Assinatura do callback de patch de dados do mapa. É usado para modificar/corrigir os dados do tilemap (por exemplo, blocos destrutíveis) antes de serem enviados à VRAM.

typedef void MapDataPatchCallback(
    Map *map,                 // estrutura Map de origem
    u16 *buf,                 // buffer com os dados de tilemap a corrigir
    u16 x,                    // posição X inicial da atualização (em tiles)
    u16 y,                    // posição Y inicial da atualização (em tiles)
    MapUpdateType updateType, // ROW_UPDATE ou COLUMN_UPDATE
    u16 size                  // tamanho do buffer (largura ou altura do
                              // tilemap, conforme o tipo de atualização)
);

MapDefinition

Estrutura com os dados de um fundo de nível grande, otimizada para codificar mapas extensos em blocos de 128×128 pixels organizados em metatiles. Normalmente gerada pelo rescomp a partir do recurso MAP.

typedef struct
{
    u16 w;                // largura do mapa em blocos (128x128 pixels)
    u16 h;                // altura do mapa em blocos (128x128 pixels)
    u16 hp;               // altura em blocos removendo linhas duplicadas
    u16 compression;      // b0-b3 = compressão dos metaTiles,
                          // b4-b7 = compressão dos blocks,
                          // b8-b11 = compressão dos blockIndexes
                          // (COMPRESSION_NONE / APLIB / LZ4W)
    u16 numMetaTile;      // número de metatiles
    u16 numBlock;         // número de blocos (chunks de 128x128 pixels)
    u16 *metaTiles;       // metatiles (blocos 2x2 tiles); cada entrada:
                          // b15 = prioridade, b14-b13 = paleta,
                          // b12 = vflip, b11 = hflip, b10-b0 = índice do tile
    void* blocks;         // blocos (8x8 metatiles); índice de 8 bits se
                          // numMetaTile <= 256, senão 16 bits
    void* blockIndexes;   // índices de bloco para o mapa w * hp; índice de
                          // 8 bits se numBlock <= 256, senão 16 bits
    u16* blockRowOffsets; // offsets de linha de bloco (uso interno):
                          // index = blockIndexes[blockRowOffsets[y] + x]
} MapDefinition;

Map

Estrutura de trabalho criada por MAP_create(..) a partir de uma MapDefinition; contém o estado do scrolling e os dados descompactados usados pelas funções MAP_xxx.

typedef struct Map
{
    u16 w;                 // largura do mapa em blocos (128x128 pixels)
    u16 h;                 // altura do mapa em blocos (128x128 pixels)
    u16* metaTiles;        // interno - dados descompactados de MapDefinition.metaTiles
    void* blocks;          // interno - dados descompactados de MapDefinition.blocks
    void* blockIndexes;    // interno - dados descompactados de MapDefinition.blockIndexes
    u16* blockRowOffsets;  // interno - acesso direto a MapDefinition.blockRowOffsets
    VDPPlane plane;        // plano do VDP onde o MAP é desenhado
    u16 baseTile;          // atributos base (offset de índice de tile e
                           // paleta base, ver TILE_ATTR_FULL())
    u32 posX;              // posição X atual da vista (via MAP_scrollTo)
    u32 posY;              // posição Y atual da vista (via MAP_scrollTo)
    // ... campos internos: máscaras/shifts de plano, lastXT/lastYT,
    // hScrollTable[240], vScrollTable[20] e callbacks internos de
    // preparação/patch/consulta (prepareMapDataColumnCB, prepareMapDataRowCB,
    // mapDataPatchCB, getMetaTileCB, getMetaTilemapRectCB)
} Map;

Map* MAP_create(const MapDefinition* mapDef, VDPPlane plane, u16 baseTile)

Cria e retorna a estrutura Map necessária para usar as demais funções MAP_xxx, a partir de uma MapDefinition. Ao terminar de usar o mapa, libere-o com MAP_release(map).

ParâmetroDescrição

planePlano onde o mapa será desenhado (para MAP_scrollTo(..)): BG_A ou BG_B. Se for usar o mapa apenas para colisão ou lógica (via MAP_getTile(..)), pode deixar 0.

void MAP_scrollTo(Map* map, u32 x, u32 y)

Rola o mapa até a posição especificada. A função cuida da atualização do tilemap do VDP (transferido pela fila de DMA) e o scroll de fundo do VDP é aplicado automaticamente no VBlank (dentro das tarefas de SYS_doVBlankProcess()).

ParâmetroDescrição
mapEstrutura Map de origem.
xPosição X da vista desejada.
yPosição Y da vista desejada.

Atenção: a primeira chamada a MAP_scrollTo(..) faz uma atualização completa do plano — para um plano 64×32 isso representa 4 KB de dados. Como o limite é de ~7,2 KB por frame, não é possível inicializar 2 MAPs no mesmo frame; chame SYS_doVBlankProcess() entre as inicializações.

object.h Mini framework de objetos/entidades de jogo

Este módulo fornece um mini framework para gerenciar objetos de jogo (entidades, inimigos, personagens, projéteis...). Ele trabalha em conjunto com a unidade pool.h, que provê a alocação dinâmica dos objetos em pools de tamanho fixo — abordagem ideal no Mega Drive, onde alocação dinâmica genérica é cara e fragmenta memória.

A ideia é usar Object como estrutura base do seu próprio tipo: declare sua struct embutindo um Object (pode ser anônimo) sempre na primeira posição. Assim sua entidade pode ser manipulada pelas funções OBJ_xxx, com ciclo de vida em três callbacks: init (uma vez após a criação), update (normalmente uma vez por frame, disparado em lote por OBJ_updateAll) e end (uma vez antes da liberação).

struct entity_
{
    Object;          // estrutura base, sempre em primeiro
    f32 posX;
    f32 posY;
    Sprite* sprite;
    ...
};

Constantes e macros

NomeValorDescrição
OBJ_ALLOCATED0x8000Estado "alocado" do objeto (bit 15 de internalState), útil principalmente para depuração.

Tipos

ObjectCallback

Assinatura dos callbacks de objeto (init, update e end).

typedef void ObjectCallback(Object* obj); // obj = objeto alvo do callback

Object

Estrutura base de objeto, a ser embutida na primeira posição das suas próprias structs de entidade.

typedef struct Object_
{
    u16 internalState;      // estado interno; pode ser usado livremente,
                            // mas preserve o bit 15 (usado internamente
                            // para detectar objeto inválido)
    u16 type;               // tipo do objeto, para identificar a struct
                            // concreta subjacente
    ObjectCallback* init;   // callback de inicialização (chamado uma única
                            // vez após a criação)
    ObjectCallback* update; // callback de atualização (normalmente uma vez
                            // por frame)
    ObjectCallback* end;    // callback de finalização (chamado uma única
                            // vez antes da liberação)
} Object;
